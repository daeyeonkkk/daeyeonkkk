## 소개

저는 빠르게 만드는 사람보다, **이어받아 운영할 수 있는 형태로 만드는 사람**이 되고 싶습니다. AI 기능을 붙일 때도 "모델이 답했다"에서 끝내지 않고, 실패했을 때 무엇을 보여줄지, 어떤 계약을 검증할지, 어떤 근거 자료를 남길지까지 함께 설계합니다.

최근에는 다음 문제들을 많이 다뤘습니다.

- AI 작업 흐름을 사용자가 이해할 수 있는 제품 화면과 API 계약으로 감싸기
- 프론트엔드, 백엔드, AI 실행 환경, 저장소, 배포 사이의 계약 정리
- 음악, 이미지, 금융, 에이전트 플랫폼처럼 도메인 규칙이 있는 제품을 풀스택으로 구조화
- 비공개 소스와 공개 포트폴리오 표면을 분리해 공개 가능한 저장소 품질 관리

## 관심사

| 관심사 | 제가 신경 쓰는 질문 |
| --- | --- |
| 제품 엔지니어링 | 사용자는 어떤 모델을 이해해야 하고, 어떤 복잡도는 시스템이 숨겨야 할까? |
| AI 호출 조율 | LLM/비전/오디오 모델 호출을 실패, 재시도, 검수, 운영 흐름까지 어떻게 연결할까? |
| 백엔드 계약 | API 스키마, 저장소 모델, 작업 상태, 검증 자료 묶음을 어떻게 작고 검증 가능하게 만들까? |
| 프론트엔드 사용성 | 복잡한 상태를 설명문 없이도 누를 수 있는 화면으로 어떻게 바꿀까? |
